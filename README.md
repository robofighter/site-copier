# site-copier

Локальная система для копирования произвольных **Framer-сайтов** в статические,
готовые к развёртыванию папки. Управление — через встроенную веб-панель.

Каждое задание проходит путь: **URL → краулинг (Browsertrix в Docker) →
конвертация WACZ → папка `site/` + ZIP**. Копия полностью автономна: все
ассеты локальные, ни одного внешнего запроса, промо-бейджи Framer («Made in
Framer», «Buy template», «Remix» и т.п.) вырезаны.

---

## Возможности веб-интерфейса

Панель (`static/index.html` + `app.js` + `style.css`) даёт:

- **Создание задания**: URL, область обхода (`host` — только этот хост, или
  `domain` — все поддомены), лимит страниц, число воркеров (1–8), лимит
  времени, поведения Browsertrix (`autoplay,autofetch,autoscroll,siteSpecific`
  по умолчанию), селекторы для скрытия элементов.
- **Список заданий** со статусами и стадиями (`queued → crawl → convert →
  done/error`), количеством страниц, размером, временем создания.
- **Журнал задания** — живой лог этапов.
- **«Открыть»** — предпросмотр копии в браузере: на каждое задание
  поднимается свой мини-HTTP-сервер на отдельном порту с заголовком
  `no-store`, поэтому корне-абсолютные пути `/assets/...` и service worker
  работают ровно как при реальном размещении.
- **«Скачать ZIP»** — готовый архив копии (`site.zip`).
- **«Перечитать»** — пересканирует каталог `jobs/` без перезапуска панели
  (полезно, если задания собирались вручную).

## Зависимости

| Что | Зачем | Обязательно |
|---|---|---|
| **Docker** (OrbStack на macOS / Docker Desktop / docker-ce на Linux) | Краулинг в контейнере Browsertrix | ✅ |
| Образ `webrecorder/browsertrix-crawler:1.15.0` | Сам краулер (тянется автоматически при первом задании, либо `docker pull`) | ✅ |
| **Python 3.8+** (проверено на 3.12) | Панель и конвертер | ✅ |
| Python-пакеты из pip | **не нужны** — весь код использует только стандартную библиотеку | — |
| Node.js + Playwright | только для авто-проверки клонов в браузере (внешние скрипты, в проект не входят) | ⬜ опционально |

`crawler.py` сам проверяет наличие Docker и образа (`GET /api/status` показывает
их состояние) и при необходимости скачивает образ.

## Быстрое развёртывание с нуля

```bash
# 1. Docker (macOS)
brew install orbstack && open -a OrbStack
# Linux: sudo apt install docker.io && sudo usermod -aG docker $USER

# 2. Проект
git clone https://github.com/robofighter/site-copier.git
cd site-copier

# 3. (опционально) заранее скачать образ краулера
docker pull webrecorder/browsertrix-crawler:1.15.0

# 4. Запуск панели (порт по умолчанию 8200, можно свой: PORT=9000)
python3 server.py

# 5. Открыть в браузере
# http://127.0.0.1:8200
```

Дальше всё через панель: вставить URL → «Запустить» → дождаться статуса
`done` → «Открыть» для предпросмотра или «Скачать ZIP» для выгрузки.

Переменные окружения:

- `PORT` — порт панели (по умолчанию `8200`);
- `BTRIX_IMAGE` — тег образа краулера (по умолчанию `webrecorder/browsertrix-crawler:1.15.0`).

## Структура проекта

```
site-copier/
├── server.py      # веб-панель: задания, статусы, ZIP, предпросмотр, API
├── crawler.py     # обёртка над Browsertrix Crawler в Docker
├── convert.py     # WACZ → статическая папка (переписывание URL, чистка)
├── warcutil.py    # разбор WACZ/WARC, извлечение записей
├── static/        # интерфейс панели (index.html, app.js, style.css)
└── jobs/          # артефакты заданий (в git не идёт)
    └── <id>/
        ├── crawl/ # WACZ от краулера
        ├── site/  # готовая копия сайта
        ├── site.zip
        └── job.json
```

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/status` | состояние Docker и образа |
| GET | `/api/jobs` | список заданий |
| POST | `/api/jobs` | создать задание (`{url, scope, limit, workers, timeLimit, behaviors, hideSelectors}`) |
| GET | `/api/jobs/<id>` | детали задания + лог |
| GET | `/api/jobs/<id>/download` | скачать `site.zip` |
| GET | `/api/jobs/<id>/open` | URL предпросмотра |
| GET | `/api/jobs/<id>/preview/<путь>` | файл копии (со корректными MIME) |
| POST | `/api/jobs/rescan` | перечитать `jobs/` с диска |

## Как это работает (коротко)

1. **Краулинг** (`crawler.py`): `docker run webrecorder/browsertrix-crawler`
   складывает WACZ. Краулинг идёт **в именованный том Docker**
   (`sitecopier-<хэш>`), затем результат копируется обратно помощником-контейнером,
   том удаляется. Это обходит жёстко зашитый в Browsertrix порог
   `usedPercentage >= 99` — на хосте, забитом под 99%, краулинг иначе падает
   сразу со «Out of disk space», даже если свободно много гигабайт.
2. **Конвертация** (`convert.py`): WACZ → WARC → файлы. Абсолютные URL
   переписываются в локальные; в HTML/JS внедряется шим `new URL()`, без
   которого Framer-гидрация падает на корне-абсолютных путях и страница
   остаётся белой; вырезаются панели редактора Framer; через
   MutationObserver удаляются промо-бейджи, которые появляются уже после
   гидратации.
3. **Готово**: папка `site/` (можно просто залить на любой хостинг) + ZIP.

## Проверено на

| Сайт | Страниц | Результат |
|---|---|---|
| oberon.framer.website | 8 | hyd=Y, imgs 36/37, ext=0, 4xx=0, errs=0, промо=0 |
| kyma.framer.ai | 27 | hyd=Y, imgs 31/31, ext=0, 4xx=0, errs=0, промо=0 |
| precept.framer.website | 33 | hyd=Y, imgs 25/25, ext=0, 4xx=0, errs=0, промо=0 |

`hyd=Y` — отработала Framer-гидрация (главный признак «не белый экран»),
`ext=0` — ноль обращений к внешним серверам.

## Известные грабли

- **«Out of disk space» при старте краулинга** — не про свободные гигабайты, а
  про процент занятого места (порог 99% в Browsertrix). Решение уже встроено:
  краулинг в том Docker. Если том создать не удалось, `crawler.py` честно
  откатывается на прямой каталог задания и пишет об этом в лог.
- **Переменные `HTTP_PROXY`/`HTTPS_PROXY` в окружении** ломают ручные проверки
  через `curl` (502) и Chromium (`ERR_PROXY_CONNECTION_FAILED`). Для панели
  не критично; при ручной проверке используйте `curl --noproxy '*'` и
  `--no-proxy-server` у браузера.
- `jobs/`, `previews/`, `crawls/`, `__pycache__`, `*.zip` — артефакты рантайма,
  в git не идут (см. `.gitignore`).
